# Offline Study Catalog and Persistent Ratings

**Date:** 2026-08-15
**Status:** approved by direct implementation instruction
**Target:** XIAO ESP32-S3 Plus, 16 MiB flash, 8 MiB PSRAM
**Source database:** `../kanjis-backend/data/kanjis-backend.sqlite3`

## 1. Objective

Make the board useful with no network, laptop, proxy, or provisioned Wi-Fi. It
must boot directly into a real study card, traverse every card in the selected
user's ten JLPT decks, accept the four existing ratings, and restore both the
current position and rating state after power loss.

The existing remote source remains available when configured and connected,
but online synchronization and server-side FSRS reconciliation are explicitly
deferred. This project establishes the durable local data path that a later
sync project can consume.

## 2. Measured source and flash budget

The live database contains ten deck templates and 9,956 card templates:

- 989 kanji cards and 8,967 vocabulary cards.
- N1: 3,340; N2: 2,806; N3: 1,840; N4: 1,189; N5: 781.
- Both user rows resolve to the same 9,956 card contents. The exporter selects
  one user deterministically by maximum active card/deck coverage unless an
  explicit user id is supplied.
- Every card has meanings, a shape explanation, a mnemonic reason, and at
  least one component. `principle` exists on all 989 kanji cards and is absent
  on vocabulary cards by design.

The current partition table ends the 8 MiB factory application at `0x810000`.
Exactly `0x7F0000` bytes remain before the end of the 16 MiB device. Allocate
the complete remainder as follows:

| Partition | Type/subtype | Offset | Size | Policy |
|---|---:|---:|---:|---|
| `catalog` | `0x40/0x00` | `0x810000` | `0x770000` | raw, read-only |
| `study_state` | `0x41/0x00` | `0xF80000` | `0x080000` | raw, mutable |

Both offsets and sizes are 4 KiB aligned and the final byte ends exactly at
`0x1000000`. The firmware retains its existing 8 MiB application slot and does
not add OTA slots.

## 3. Scope

### Included

- A deterministic, read-only exporter from the live SQLite database.
- All ten decks and all 9,956 cards; no random down-sampling.
- Full source prose and all source senses/components within the measured real
  maxima, without the current display projection's truncation.
- A block-indexed compressed binary image and bounds-checked portable decoder.
- A raw ESP partition reader with CRC and schema validation.
- A power-loss-safe, append-only single-user rating store in `study_state`.
- A balanced, deterministic offline traversal across per-deck shuffled cards.
- Immediate offline startup even without saved Wi-Fi.
- Local grade submission and next-card advance without HTTP.
- Host tests, generator tests, partition assertions, a full firmware build, and
  documentation for generating/flashing the catalog.

### Excluded

- The dense one-page answer UI and the tiny grade-strip visual redesign; that
  is the next project after this offline data path works.
- Uploading local ratings to the backend or reconciling them with remote FSRS.
- Wall-clock due scheduling. The board has no battery-backed RTC; this phase
  records durable four-grade outcomes and advances the deterministic local
  sequence without pretending to calculate a trustworthy due date.
- Comments, comment threads, images, audio, shorts, reactions, annotations,
  sessions, remote reviews, user deck settings, templates as runtime objects,
  and duplicated user card rows.
- Filesystems, per-card JSON files, SQLite on the device, and loading the whole
  catalog into RAM.

## 4. Export projection

The exporter opens SQLite with `mode=ro`, never runs migrations, and never
writes alongside the source database. It resolves one user's deck coverage,
then projects common card-template content only.

Each card record contains:

- Stable source card id and deck index.
- `front`, short gloss with `senses[0]` fallback, all senses (measured max 5).
- Structured on/kun readings and a collapsed display reading.
- Full `back.shape_explanation` (measured max 819 UTF-8 bytes).
- Source `hint.principle` when present; it is never inferred.
- Every `hint.shapes` component (measured max 6), preserving glyph, meaning,
  and source reading when present. The 35 cards with a missing component
  reading keep an empty cell rather than receiving a fabricated reading.
- Full `hint.reason` mnemonic (measured max 615 UTF-8 bytes).
- A safe composition equation generated by the existing kanjis-front rule:
  self-reference is removed for a single kanji, compound sub-radicals are not
  promoted to headword components, and the actual result glyph is retained.

The exporter removes UUID ownership data from runtime records, timestamps,
tags redundant with the deck, duplicate `back.kanji`, examples, comments,
media URLs, and every unused source key. It validates UTF-8, record maxima,
unique stable ids, deck/card counts, and the final partition budget.

## 5. Catalog image format

The image is deterministic for a given schema, source digest, target user, and
seed. Per-deck cards are sorted by a SHA-256-derived seeded key and then
round-robin interleaved across decks. The resulting ordinal is the offline
study order: it is random-looking inside every deck, balanced while multiple
decks still contain cards, reproducible across builds, and requires no queue in
RAM.

Cards are serialized as compact, card-only JSON envelopes using the existing
board wire names. The envelope is length-indexed by the surrounding binary
format and excludes session, comments, examples, media, and remote FSRS data.
Reusing `kanji_parse()` keeps network and catalog cards on one validated model
projection instead of introducing a second semantic decoder. Sixty-four
consecutive envelopes form one zlib-wrapped DEFLATE block. The measured source
produces approximately 3.11 MB total. Block and record offsets are 32-bit; a
block is rejected above the explicit 96 KiB uncompressed safety limit (the
audited full projection peaks below 77 KiB).

The image contains:

1. A fixed little-endian header with magic, schema version, used size, counts,
   section offsets, deterministic seed, source SHA-256, catalog id, and CRC32.
2. A deck table with level, type, display name, and card counts.
3. One compact card index entry per ordinal: block id, record offset, and
   record length.
4. One block entry per 64-card block: compressed offset/length, uncompressed
   length, and uncompressed CRC32.
5. The zlib blocks.

The generator hard-fails if the image exceeds `0x770000`, if a section
overlaps another, if a block exceeds 96 KiB uncompressed, or if the source does
not contain exactly ten decks and 9,956 unique card records for the selected
catalog.

## 6. Portable decoder and model

`vault_core` owns a portable reader over an injected `read_at(offset, dst,
length)` callback. Host tests use a memory image; ESP uses
`esp_partition_read()`. Initialization validates header magic/version/CRC,
all offset arithmetic with overflow checks, table bounds, counts, and the
catalog partition limit before exposing any card.

Reading a card loads one compressed block and inflates it with zlib into PSRAM,
checks the block CRC and the indexed record bounds, and passes the exact bounded
span directly to `kanji_parse(json, length)`. That parser already uses cJSON's
length-aware non-NUL-terminated entry point. Only the deck table, one compressed
block, and one uncompressed block are resident; the 7.44 MiB partition is never
mapped or copied wholesale.

The model capacities increase to the measured full-fidelity bounds: five
senses, six parts, at least 820 bytes for each prose field, at least 141 bytes
per sense, and enough reading/formula space for the audited maxima. The model
also gains explicit gloss, on-reading, kun-reading, composition equation, and
source kind. Network parsing remains backward compatible.

Any invalid header, CRC, offset, DEFLATE stream, UTF-8 field, or record count
rejects the candidate card without replacing the last valid snapshot. On a
cold boot with an invalid or missing catalog, the existing built-in mock is the
final fallback and the device remains operable.

## 7. Persistent single-user state

`study_state` is split into two 256 KiB banks. Each bank has a versioned header
containing generation, catalog id, and header CRC. A bank becomes eligible only
after its commit marker is written last. At boot the newest valid committed
bank is selected.

Ratings append fixed-size little-endian records containing sequence number,
card ordinal, next ordinal, grade, repetitions, lapses, flags, and CRC32. The
record is valid only when every field and CRC has been written. A torn tail is
ignored, leaving the previous record authoritative.

The runtime replays records into a compact per-card summary in PSRAM. When the
active bank lacks room, the inactive bank is erased, one latest summary per
reviewed card is written in ordinal order, its commit marker is written, and
only then may the old bank be erased. A power loss at every step leaves at least
one previously committed bank readable.

Submitting a local grade follows one ordering rule:

1. Calculate the next catalog ordinal.
2. Append and verify the rating record.
3. Update RAM state.
4. Decode the next card.
5. Publish it and reset navigation to the question.

If persistence fails, the current answer remains visible and the card does not
advance. Every accepted grade advances one ordinal regardless of grade in this
phase; the grade changes persisted repetitions/lapses/last-grade state, not a
wall-clock schedule.

## 8. Runtime source arbitration and boot

The app uses an explicit source enum: `CATALOG`, `REMOTE`, or `DEMO`.

- Catalog initialization occurs before Wi-Fi connection attempts.
- `UiTask` and buttons start immediately with the restored local card.
- No saved Wi-Fi or a failed station join returns to offline study instead of
  blocking forever in the setup portal.
- The setup portal is entered only through the existing long-press escape hatch
  and may intentionally overlay the study UI then.
- A configured remote source may replace the catalog after a successful fetch.
- A remote failure never consumes a local card or silently redirects a remote
  grade to the catalog.
- A catalog grade is persisted locally and advances locally without HTTP.
- Clearing the remote URL returns to the restored catalog card, not the demo.
- The companion API starts only after a successful network connection.

The prior source-generation guard remains authoritative for stale HTTP
responses. Source transitions reset navigation and force one full refresh.

## 9. Build and flash integration

The project adds the official `espressif/zlib` component and links it only to
the catalog decoder/store path. A Python generator target writes the catalog
image under the build directory. The source DB path, optional user id, and seed
are CMake cache variables/environment overrides; the default sibling-repo path
matches this workspace.

The catalog image is registered with ESP-IDF's partition flashing helper so a
normal full `idf.py flash` writes it to `catalog`. `app-flash` deliberately
updates firmware only and is documented as not updating catalog content.
Generated images remain untracked build artifacts.

Build assertions resolve `partitions.csv` and fail unless:

- `catalog` begins at `0x810000`, is exactly `0x770000`, and is read-only.
- `study_state` begins at `0xF80000` and is exactly `0x080000`.
- The final partition ends at `0x1000000` without overlap.
- The generated catalog is no larger than the catalog partition.
- The application fits the existing 8 MiB slot with at least 512 KiB spare.

## 10. Acceptance tests

### Generator

- A fixed fixture produces byte-identical images across two runs.
- The actual read-only database produces exactly 10 decks and 9,956 cards.
- The `財` golden record contains `형성`, `貝 + 才 = 財`, both component rows,
  full origin prose, and full mnemonic prose.
- Compound and okurigana formula golden cases match kanjis-front behavior.
- Excluded comments/media/user/session keys cannot be found in decoded output.
- The 819-byte origin, 615-byte mnemonic, five senses, six parts, and missing
  component-reading cases survive a round trip.

### Decoder

- Header, table, block, record, UTF-8, integer-overflow, truncation, CRC, and
  DEFLATE corruptions are rejected.
- First, last, and every 64-card boundary ordinal decode correctly.
- A rejected read leaves the caller's previous `kanji_t` unchanged.

### State

- A grade survives a reconstructed store/reboot.
- A torn record preserves the previous current card and rating state.
- Power loss before and after bank commit always selects a valid generation.
- Compaction retains the latest summary for every reviewed card.
- A catalog-id mismatch starts a fresh local state rather than applying grades
  to changed ordinals.

### Runtime and firmware

- No credentials boots a catalog card and responsive buttons without opening a
  portal automatically.
- A catalog grade persists, advances, and returns to the question screen.
- A failed local state write does not advance.
- Remote success, remote failure, URL clearing, and stale-response guards retain
  their distinct behavior.
- All host suites, Python tests, simulator build, firmware build, partition
  image checks, and application-size check pass from a clean build.

## 11. Data provenance constraint

The database and repositories do not carry card-level license or attribution
metadata. This implementation is appropriate for the user's local device and
does not publish or redistribute the generated catalog image. Distribution of
that artifact requires a separate rights review.
